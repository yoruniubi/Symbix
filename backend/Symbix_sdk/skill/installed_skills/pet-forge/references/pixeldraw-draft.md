# Pet Forge — pixeldraw 草稿模式(可选)

> 借助内置 MCP `pixeldraw(像素画)` 先把形象**画出来看效果**,和用户来回改到满意,
> 再把定稿的像素布局**转录成 rig SVG**,走正常校验/打包流程。
> 适合用户对形象没想清楚、或反复要求「眼睛再大点/耳朵再圆点」的场景;
> 形象描述已经很明确时直接写 SVG 更快,**不要为了用而用**。

## 什么时候用

| 场景 | 建议 |
|---|---|
| 用户描述模糊(「画个可爱的小猫」) | 先草稿:2-3 笔摆出轮廓给用户看 |
| 用户在多个方向上犹豫 | 画 2-3 个小草稿(每次 create_canvas 换内容)让用户挑 |
| 描述已经很具体(「白猫,蓝眼睛,戴红围巾」) | 直接写 SVG,跳过草稿 |
| 已有 rig,只想改某个部位 | 直接改 SVG;草稿只用于整体重构 |

## 画布与坐标换算

rig 画板是 192×208。草稿画布二选一,**转录时坐标乘以倍率**:

| 草稿画布 | 倍率 | 适用 |
|---|---|---|
| **48×52(推荐)** | ×4 | 大多数形象;笔数少、迭代快 |
| 96×104 | ×2 | 细节多(花纹、配饰)的复杂形象 |

- `create_canvas {"width":48,"height":52,"palette":"24"}` — 24 色足够草稿用。
- 注意画布**宽高比必须保持 192:208**(即 48×52 / 96×104),别画成 48×48,否则转录后形象比例失真。
- 每个服务实例只有一张画布:`create_canvas` 会**替换**旧画布并清空撤销历史;重启进程画布就没了,想留底尽早 `save_image`。

## 色板对照表(先定再画)

开始画之前,先把「草稿用什么 MARD 色号 ↔ rig 用什么变量」写在回复里,转录时照表替换
(色号先用 `list_colors` 查当前色表,**不要臆造色号**;24 色表可用:雪白 H2/浅灰 H3/
中灰 H4/纯黑 H7/明黄 A4/中国红 F5/湖蓝 C4/肉粉 E11 等):

```
草稿色板(示例,按形象实际替换):
- H3(浅灰) → var(--pet-primary)    # 主体毛色
- H2(雪白) → var(--pet-secondary)  # 脸部/肚皮
- H7(纯黑) → var(--pet-line)       # 描边
- C4(湖蓝) → var(--pet-pupil)      # 瞳孔
- H2(雪白) → var(--pet-eye)        # 眼白
- E11(肉粉) → var(--pet-accent)    # 鼻子/腮红
```

先调 `list_colors` 查色号再挑色;MARD 色号只是草稿视觉代理,最终颜色由 theme.json 的
palette 决定,转录后草稿色不保留。

## 画法建议

- 多笔一次提交用 `draw_batch {"ops":[...]}`,`ops` 项用 `type` 区分
  (`{"type":"rect","x0":..,"y0":..,"x1":..,"y1":..,"color":..,"fill":true}`),
  原子执行、整批只回最终预览;散点用 `draw_pixels {"pixels":"x y 色号 ..."}`。
- **直接画像素阶梯**,不要用圆/椭圆工具:rig 契约(P5)要求整数格矩形+折线拼圆,
  草稿阶段就按阶梯画,转录时照抄阶梯,所见即所得。
- 最小特征 ≥ 2×2 草稿格(rig 侧是 4×4 实格;瞳孔最小 2×2 rig 格,即草稿里也要 ≥2 格宽)。
- 每画 1-2 笔就停下等预览:pixeldraw 每次绘制都返回 8 倍放大 PNG,聊天页会显示
  「绘图预览」卡,用户直接看图提意见,比文字描述高效得多。

## 转录成 rig(定稿后)

1. **逐格转矩形**:把草稿的 `draw_pixels` 落点按「横向连续 run」合并成 `<rect>`,
   坐标 ×倍率。草稿格 (x, y, w=1) → rig `<rect x="{x*4}" y="{y*4}" width="4" height="4">`;
   连续 3 格 → width="12"。多个同色相邻行可再合并成大矩形,减少节点数。
2. **分部件**:落点归进 `<g id="...">`——
   - 身体 → `body`;左右眼外框 → `eye-right`/`eye-left`(**只写 right, left 由脚本镜像**,
     除非两侧真的不一样);瞳孔 → `pupil-right`;嘴 → `mouth`;
     耳/手/尾/配饰 → `ear-right` / `limb-right` / `tail` / `accessory`。
   - 每个部件 `transform-origin` 用该部件包围盒中心(×倍率后的 rig 坐标)。
3. **颜色替换**:按色板对照表把每个色块换成对应 `var(--pet-*)`,**禁止**保留 hex。
4. **根节点**:根 `<svg viewBox="0 0 192 208">` 的 `style` 里声明全部用到的 `--pet-*`
   具体色值(theme.json palette 会再统一,但变量必须先有值)。
5. 转录完成 → **走正常流程**:`validate_rig.py` → `derive_mirrors.py` →
   `validate_states.py` → `build_theme.py`(见 SKILL.md 工作流第 4-5 步)。

## 预览与留底

- 每次绘制的预览图由后端自动落盘并显示在聊天页,不需要你做任何事;
- 想让用户留存某个阶段的图,调 `save_image {"filename": "draft-1.png"}`,
  默认存到 pixeldraw 的输出目录,把返回的路径告诉用户即可;
- 画布会被下一次 `create_canvas` 清空——用户说「回到上一版」时,**重画**,
  不要假设画布还在。
